# Introduction

This document analyzes the spread of COVID-19 using a simple SIR model.

# Model Implementation

```{r sir-model}
# Load required packages
library(tidyverse)
library(deSolve)

# SIR model function
sir_model <- function(t, state, params) {
  with(as.list(c(state, params)), {
    dS <- -beta * S * I / N
    dI <- beta * S * I / N - gamma * I
    dR <- gamma * I
    list(c(dS, dI, dR))
  })
}

# Set parameters
params <- list(
  N = 1000000,
  beta = 0.3,
  gamma = 0.1
)

# Initial conditions
initial_state <- c(
  S = params$N - 100,
  I = 100,
  R = 0
)

# Time points and simulation
times <- seq(0, 100, by = 0.1)
results <- ode(
  y = initial_state,
  times = times,
  func = sir_model,
  parms = params
) %>% as.data.frame()
```

# Results Visualization

```{r plot}
# Create the plot
ggplot(results, aes(x = time)) +

```

# Summary Statistics

```{r summary}
# Calculate key metrics
peak_infections <- max(results$I)
peak_day <- results$time[which.max(results$I)]
final_recovered <- tail(results$R, 1)

# Create summary table
summary_stats <- data.frame(
  Metric = c("Peak Infections", "Peak Day", "Final Recovered", "Attack Rate"),
  Value = c(
    round(peak_infections),
    round(peak_day, 1),
    round(final_recovered),
    round(final_recovered / params$N * 100, 1)
  ),
  Unit = c("people", "days", "people", "%")
)

knitr::kable(summary_stats, caption = "SIR Model Results Summary")
```

💻 How to Render Your R Markdown

🎛️
RStudio GUI Method

Click the "Knit" button at the top of your R Markdown file

# 1. Open analysis.Rmd in RStudio
# 2. Click "Knit" button (or Ctrl+Shift+K)
# 3. Choose output format if prompted
# 4. View the rendered document
💾
R Console Method
# Basic rendering
rmarkdown::render("analysis.Rmd")

# Specify output format
rmarkdown::render("analysis.Rmd", output_format = "html_document")

# Render to multiple formats
rmarkdown::render("analysis.Rmd", output_format = "all")
⚡
Command Line Method
# Using Rscript from terminal
Rscript -e "rmarkdown::render('analysis.Rmd')"

# Batch processing multiple files
Rscript -e "lapply(list.files(pattern='*.Rmd'), rmarkdown::render)"

  • Figure Quality: Use dpi=300 for publication-quality plots
  • Output Formats: Try pdf_document, word_document, or github_document

Benefits of R Markdown for Research

Reproducibility

Anyone can regenerate your results by running the R Markdown file. No more "it worked on my machine" issues.

Documentation

Code, results, and explanations are all in one place. Perfect for lab notebooks and research papers.

Version Control

Track changes to both code and documentation together. See how your analysis evolved over time.

Collaboration

Team members can see exactly what you did and build upon your work. Pull requests can include both code and documentation changes.

Best Practices for R Projects

Project Organization

File Naming

Use consistent, descriptive file names:

  • 01_data_cleaning.R - Data preparation
  • 02_exploratory_analysis.R - Initial exploration
  • 03_model_fitting.R - Statistical modeling
  • 04_results_visualization.R - Creating figures

Function Organization

Separate functions into logical files:

  • R/functions_data.R - Data manipulation functions
  • R/functions_models.R - Model-related functions
  • R/functions_plotting.R - Visualization functions
  • R/functions_utilities.R - Helper functions

Data Management

Organize data files properly:

  • data/raw/ - Original, unmodified data
  • data/processed/ - Cleaned and processed data
  • data/external/ - Data from external sources
  • Never commit large data files to Git

R Coding Standards

Style Guidelines

  • Use snake_case for file and variable names
  • Use descriptive variable names (avoid x, y, temp)
  • Add comments explaining complex logic
  • Keep functions focused and short
  • Use consistent indentation (2 spaces)

Package Management

  • Use library() at the top of scripts
  • Specify package versions for reproducibility
  • Use require() sparingly
  • Document package dependencies in README

Error Handling

  • Use stopifnot() for input validation
  • Add meaningful error messages
  • Use tryCatch() for graceful failures
  • Test functions with edge cases

Git Workflow for R Projects

Daily Git Workflow for R Research

Key Principle: Commit incrementally for the smallest updates you're satisfied with. This creates a clear history and allows you to track progress throughout the day.

Iterative Development Workflow

🌅
Morning: Setup & Planning

Start your research day with proper Git setup

# Pull latest changes and start fresh
git pull origin main
git checkout -b feature/age-structured-sir

# Plan your incremental goals for the day
# Break down the feature into small, testable pieces
⚡
Throughout Day: Iterative Commits

Commit each small, working increment as you complete it

# After implementing a small feature:
git add R/age_structure.R
git commit -m "Add basic age group structure

- Define age categories (0-4, 5-14, 15-64, 65+)
- Create age group vector
- Test age structure initialization"

# Continue working, commit again when satisfied:
git add R/contact_matrix.R
git commit -m "Implement age-specific contact matrix

- Add contact rates between age groups
- Use POLYMOD survey data
- Validate matrix properties"

# Push incremental progress to remote
git push origin feature/age-structured-sir
🧪
Testing & Validation

Test each increment and commit working tests

# After each feature, add tests:
git add tests/test-age-structure.R
git commit -m "Add tests for age structure validation

- Test age group boundaries
- Validate age vector creation
- Check error handling for invalid ages"

# Run tests to ensure everything works
# Only commit when tests pass
📚
Documentation Updates

Update documentation with each significant change

# Update documentation as you go:
git add README.md
git add vignettes/age-structured-model.Rmd
git commit -m "Update documentation for age structure

- Add age group definitions to README
- Include usage examples in vignette
- Document parameter ranges and constraints"
🚀
End of Day: Integration

When satisfied with the complete feature, integrate with main

# Final push of the day
git push origin feature/age-structured-sir

# If working solo: merge to main
git checkout main
git merge feature/age-structured-sir
git push origin main

# If collaborating: create pull request
# Request review from maintainers
# Address feedback and merge when approved

Benefits of This Approach

📈
Clear Progress Tracking

See exactly what you accomplished each day with detailed commit history

🔄
Easy Rollback

If something breaks, you can easily revert to the last working increment

👥
Better Collaboration

Smaller, focused commits are easier for others to review and understand

💡
Learning & Debugging

Each commit represents a learning step, making debugging much easier

Git Tips Specific to R Projects

Commit R Markdown Files

Always commit your .Rmd files. They contain both code and documentation, making them perfect for version control.

Don't Commit Generated Files

Use .gitignore to exclude HTML, PDF, and other generated outputs. These can be regenerated from the source.

Commit Data Processing Scripts

Scripts that process raw data into analysis-ready formats should be version controlled.

Use Meaningful Commit Messages

Describe what changed and why. For R projects, mention the analysis step or model improvement.
